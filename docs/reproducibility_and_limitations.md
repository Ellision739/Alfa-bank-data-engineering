# Ограничения и воспроизводимость

Этот документ фиксирует ограничения именно тех файлов, которые сохранились в архиве команды. Он не пытается восстановить утраченный ход работы.

## Что включено

В репозитории находятся три оригинальных ноутбука, три документа Data Governance, три аналитических документа, список гипотез, перечень ETL-таблиц, изображения lineage / dashboards / ER / Kanban и итоговая презентация.

## Чего нет в исходном архиве

- SQL-скриптов трансформаций и аудита, на которые ссылаются Data Governance документы;
- исходников Apache Airflow DAG;
- Parquet-файлов `heroes_dict.parquet`, `hero_counterpick_metrics.parquet`, `hero_match_sparse.parquet`, которые ожидает ноутбук кейса №22;
- выгрузок исходных таблиц Lakehouse и среды исполнения JupyterHub.

## Зависимости от исходной среды

Ноутбуки кейсов №5 и №23 используют `lakehouse_spark` и `pyspark`, обращаются к таблицам Lakehouse. Их нельзя считать автономными скриптами, запускаемыми на обычном локальном Python без исходной платформы и таблиц.

Ноутбук кейса №22 включает SQL-шаблоны для некоторых преобразований RAW → STAGE и код построения матриц / SVD, однако загружает промежуточные таблицы из Parquet. Без отсутствующих файлов расчёт не воспроизводится из архива.

## Несогласованность результатов между артефактами

В разных материалах есть значения из разных прогонов. Например, количество пригодных матчей кейса №5 различается в ноутбуке, аналитическом тексте и презентации. По кейсу №23 показатели CLEAN / UNIQUE в Data Governance документе и в ноутбуке также относятся к разным сохранённым снимкам. Эти значения не объединялись в искусственный единый итог.

Для кейса №23 F1 по тегу `toxic` (0,80 у LLM против 0,00 у baseline) рассчитан на 286 никнеймах с черновой разметкой и 13 положительными примерами. H2 имеет точечную оценку +1,03 п. п. в сохранённом ноутбуке, но устойчивый доверительный интервал не рассчитан. Поэтому H1 — предварительный результат пилота, а H2 остаётся открытой.

## Что можно делать дальше

Если появятся исходники от участников или организаторов, их можно добавить отдельным коммитом с указанием автора / источника и без изменения сохранённых материалов. Не следует создавать новые SQL/DAG-файлы и выдавать их за исходные файлы буткемпа.
