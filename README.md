# Dota 2 Data Engineering Bootcamp — команда №8 «Полотенце»

Командный проект четырёхдневного буткемпа по Data Engineering в Томске (12–15 ноября 2026 года). Команда №8 «Полотенце» заняла **II место среди 11 команд**.

В репозитории собраны сохранившиеся Jupyter Notebook, аналитические материалы, документация по данным, визуализации и итоговая презентация. Часть вычислений выполнялась в JupyterHub/Lakehouse организаторов; ноутбуки и их сохранённые результаты доступны для ознакомления, но полный локальный запуск зависит от исходной среды и данных.

## Кейсы

1. **№5 — Bounty Runes.** Анализ связи подбора рун в начале матча с преимуществом по золоту и взятием первой башни.
2. **№22 — герои и драфт.** Анализ паттернов выбора героев с использованием SVD, поиск похожих героев и исследование контр-пиков.
3. **№23 — классификация никнеймов.** Нормализация и дедупликация игровых никнеймов, пилотная LLM-классификация по тегам и сравнение с rule-based baseline.

## Командное решение

В материалах команды описана схема обработки `RAW → STAGE → MART`. Общая архитектура включала PostgreSQL и MongoDB, Apache Airflow, Apache Spark / Spark SQL, Apache Iceberg и MinIO, Trino, Apache Superset, Marquez / OpenLineage.

Это описание общего стека командного решения. Роли участников распределялись между дата-инжинирингом, аналитикой данных и аналитической проработкой кейсов.

## Мой вклад — кейс №23

Я отвечал за аналитическую проработку задачи классификации никнеймов: постановку задачи, критерии тегирования и оценку результатов LLM относительно rule-based baseline.

В пилотной выборке из **286 никнеймов** (13 положительных примеров для тега `toxic`) F1 LLM составил **0,80** против **0,00** у baseline. 95%-й bootstrap-интервал разницы F1 с поправкой на пять тегов: **[0,5263; 0,9655]**. Эталонная разметка была черновой, поэтому результат характеризует этот пилотный прогон.

## Запуск и ограничения

- Ноутбуки №5 и №23 используют `lakehouse_spark` и таблицы Lakehouse; для полного выполнения нужна среда JupyterHub/Lakehouse организаторов. Сохранённые outputs позволяют просмотреть ход работы без повторного запуска.
- Ноутбук №22 зависит от промежуточных Parquet-данных, которых нет в сохранённом архиве. Отдельные SQL-трансформации и Airflow DAG также не сохранились.
- В разных материалах встречаются результаты разных снимков данных и прогонов. Для кейса №23 метрика F1 выше относится к указанной пилотной выборке и черновой эталонной разметке.
